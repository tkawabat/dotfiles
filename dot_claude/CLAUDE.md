# CLAUDE.md (User-level / Home)

すべての Claude Code セッションで読み込まれる、ユーザー個人のグローバル設定。
プロジェクト固有の指示は各プロジェクト直下の `CLAUDE.md` に書く。

## 言語

- 日本語で応答する。

## 一般的なふるまい

- 不要な前置きや末尾の要約は省く。差分やコマンド出力で伝わることを文章で繰り返さない。
- 不確実な点を勝手に推測で埋めず、必要なら短く確認する。
- 大きな副作用を伴う操作（破壊的な git 操作、外部システムへの送信など）は事前に確認する。

## コードコメント

1. コードコメントは基本的に残さない。残すなら Why / Why not だけ。
- 書く：なぜこの実装にしたか、なぜ自然に見える別解を採らなかったか（仕様・既知バグ回避・互換性・性能など、コードを読んでも分からない外部要因）
- 書かない：What / How（読めば分かること）、処理の言い換え、引数・戻り値・型・レスポンス形状の説明、変更履歴、TODO 代わりの独り言

2. 型・引数・戻り値はコメントじゃなくコードで表現する。
TypeScript の型注釈・Ruby の Sorbet sig で書き、@param / @return をコメントで代替しない。

3. PR 説明文・コミットメッセージ・Notion・回答も同じ扱い。
できる限り簡潔に、要点だけ。自明なことは書かない。小学生でもわかる言葉で（専門用語は言い換えを添える）。

4. 残すと決めたコメントの書き方
- 日本語の改行は句点「。」読点「、」や意味のまとまりで折る。語句の途中で改行しない
- 長い説明は行コメントを並べず JSDoc（/** ... */）などブロック形式にする

## 環境

- dotfile は `chezmoi` で管理しており、元のファイルは `~/git/dotfiles` リポジトリ以下にある。`$HOME` 側を直接編集してもソースには反映されないので、必ずリポジトリ側を編集する。
- `mise` がインストールされており、node・python などのランタイムを管理している。
